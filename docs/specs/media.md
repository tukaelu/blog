# 機能仕様書：メディア管理

最終更新: 2026-08-26
関連ドキュメント: `requirements.md`（§5.6）, `architecture.md`（§3, §8.1）

## 1. 概要

記事本文・アイキャッチに使用する画像のアップロード・一覧表示・削除・配信を提供する。原本はCloudflare R2にそのまま保存し、配信時に**Cloudflare Image Transformations**（旧称：Image Resizing）でオンザフライにリサイズ・最適化する構成とする。

## 3. 画面仕様

### 3.1 メディアライブラリ画面（`/admin/media`）

- グリッド形式でアップロード済み画像のサムネイルを一覧表示（新しい順）
- 各サムネイルにファイル名・サイズ・アップロード日時・削除ボタンを表示
- 画面上部に「アップロード」ボタン（クリックでファイル選択）とドラッグ&ドロップ領域を配置
- アップロード中はサムネイル位置にプログレス表示

### 3.2 記事エディタからの画像挿入

- エディタツールバーの「画像」ボタン押下で、「メディアライブラリから選択」／「新規アップロード」のタブ切り替えを持つモーダルを表示
- 新規アップロードを選んだ場合、アップロード完了後そのまま本文への挿入まで一続きで行う

### 3.3 アイキャッチ画像の選択

- 記事編集画面のサイドパネルに、3.2と同様のモーダルを呼び出す「アイキャッチを設定」ボタンを配置

## 4. API仕様

### 4.1 `POST /api/admin/media`

画像アップロード（`multipart/form-data`）。

**Request**: フォームフィールド `file`（バイナリ）

**バリデーション**

| 項目           | ルール                                                              |
| -------------- | ------------------------------------------------------------------- |
| MIMEタイプ     | `image/jpeg` \| `image/png` \| `image/webp` \| `image/gif` のみ許可 |
| ファイルサイズ | 上限10MB                                                            |

**Response 201**

```json
{
  "id": "media_00000001",
  "r2Key": "media/media_00000001.jpg",
  "mimeType": "image/jpeg",
  "width": 1600,
  "height": 900,
  "url": "/media/media_00000001.jpg",
  "createdAt": "2026-08-25T10:00:00Z"
}
```

**Response 400**：MIMEタイプ不正・サイズ超過時、理由を含むエラーメッセージを返す

### 4.2 `GET /api/admin/media`

一覧取得。

**Query**: `?page=1&limit=30`

**Response 200**

```json
{
  "media": [
    {
      "id": "media_00000001",
      "url": "/media/media_00000001.jpg",
      "mimeType": "image/jpeg",
      "width": 1600,
      "height": 900,
      "createdAt": "2026-08-25T10:00:00Z"
    }
  ],
  "pagination": { "page": 1, "totalPages": 2, "totalCount": 45 }
}
```

### 4.3 `DELETE /api/admin/media/:id`

R2オブジェクトと `media` テーブルのレコードを削除する。

- 記事からの参照有無はチェックしない（§8決定事項参照）。削除確認ダイアログで「記事内で使用中の場合、表示できなくなります」という注意文言を表示するに留める

**Response 204**

### 4.4 `GET /media/:key`（公開・認証不要）

R2に保存された画像を配信する公開エンドポイント。記事詳細ページの`<img>`タグやOGP画像生成等から参照される。

**Cloudflare Image Transformationsとの連携**：配信時にリサイズ・フォーマット変換したい場合は、`/cdn-cgi/image/<options>/media/:key` の形式でアクセスする（Cloudflareのエッジでオンザフライ変換される。例：`/cdn-cgi/image/width=800,quality=85,format=auto/media/media_00000001.jpg`）。オリジナル画像はR2に1つだけ保持し、複数サイズを事前生成・保存する必要はない。

## 5. データ仕様

`architecture.md` §3.2 の `media` テーブル定義を参照。

| カラム             | 補足                                                                           |
| ------------------ | ------------------------------------------------------------------------------ |
| `r2_key`           | `media/{id}.{拡張子}` の命名規則で統一する                                     |
| `width` / `height` | アップロード時にファイルヘッダーから抽出して記録する（フルデコードは行わない） |

---

## 6. 処理フロー

### 6.1 アップロード

1. クライアントが `POST /api/admin/media` へファイルを送信する（Worker経由でR2へ直接プロキシする方式とし、事前署名URLの発行は行わない。個人ブログ規模の画像サイズであればWorkerのリクエストボディサイズ上限内に収まるため、シンプルさを優先する）
2. Worker側でMIMEタイプ・サイズをバリデーションする
3. R2へ画像を保存する（`media/{id}.{拡張子}`）
4. 画像ヘッダーから幅・高さを抽出し、`media` テーブルへメタデータを記録する
5. 生成した`media`オブジェクトを返す。呼び出し元（記事エディタのモーダル等）はこれを使って本文への挿入・アイキャッチ設定を行う

### 6.2 配信

1. 記事詳細ページのレンダリング時、画像URLは `/cdn-cgi/image/<options>/media/:key` の形式で構築する（表示サイズに応じた`width`パラメータ等を指定）
2. Cloudflareのエッジがこのパスを解釈し、初回リクエスト時にオンザフライで変換・キャッシュする。以降は同一パラメータの組み合わせであればキャッシュから返す（Cloudflare Image Transformationsの「ユニークな変換」単位での無料枠消費、§8参照）

## 7. エラーハンドリング

| ケース                                                   | 挙動                                                                                              |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| MIMEタイプ不正                                           | 「対応していないファイル形式です（JPEG/PNG/WebP/GIFのみ）」                                       |
| ファイルサイズ超過                                       | 「ファイルサイズが上限（10MB）を超えています」                                                    |
| R2への保存失敗                                           | エラートースト「アップロードに失敗しました。再度お試しください」                                  |
| Image Transformationsの無料枠超過（月5,000ユニーク変換） | `onerror`パラメータで変換前の元画像（R2の原本）へフォールバックし、リサイズなしでそのまま配信する |

## 8. 受け入れ基準

- [x] 画像をアップロードでき、メディアライブラリに一覧表示される（フェーズ5実装・Playwrightで実地検証済み）
- [x] 記事エディタから画像を選択・新規アップロードして本文に挿入できる
- [x] アイキャッチ画像を設定できる
- [x] 画像を削除できる
- [x] 配信時にCloudflare Image Transformationsでリサイズされた画像が表示される（トップページのカバー画像のみ。記事詳細本文中の画像は原寸配信）
- [x] 対応していないファイル形式・サイズ超過時に適切なエラーメッセージが表示される
- [ ] Image Transformationsの無料枠超過時の`onerror`フォールバックは未実装（発生頻度が低いため後回し、§9参照）

## 9. 決定事項・未決事項

**壁打ちを通じて決定した事項**

| 項目                                                   | 決定                                                                                                                                                                                                                     |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 画像最適化の実装方式                                   | Cloudflare Image Transformations（無料プランで月5,000ユニーク変換まで無料）を採用。R2を原本ストレージとし、複数サイズを事前生成・保存しない                                                                              |
| アップロード方式                                       | Worker経由の直接プロキシ（事前署名URL方式は採らない）                                                                                                                                                                    |
| 削除時の参照チェック                                   | 行わない。確認ダイアログでの注意喚起に留める                                                                                                                                                                             |
| ファイルサイズ上限                                     | 10MB                                                                                                                                                                                                                     |
| 無料枠超過時のフォールバック                           | `onerror`パラメータで変換前の元画像へフォールバックする                                                                                                                                                                  |
| r2_keyから配信URLへの変換（フェーズ5実装時に決定）     | `r2_key`は`media/{id}.{ext}`形式でそのままDBに保存し、配信パス`/media/:key`はR2キー全体（`media/`プレフィックス込み）と一致させる。`server/utils/media.ts`の`mediaUrl()`/`transformedMediaUrl()`に変換ロジックを集約する |
| Image Transformations適用範囲（フェーズ5実装時に決定） | トップページのカバー画像一覧表示にのみ適用（`width=400,quality=85,format=auto`）。記事本文中の画像・アイキャッチのプレビュー表示は原寸のまま配信する。無料枠消費を抑えるため、変換パターンを絞る                         |

**未決事項**

1. Image Transformationsの無料枠超過時の`onerror`フォールバックは未実装（§8参照）。実運用でユニーク変換数を計測してから対応要否を判断する
