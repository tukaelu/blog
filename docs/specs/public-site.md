# 機能仕様書：公開サイト（トップ・記事詳細・タグ一覧・検索・いいね・OGP・RSS）

最終更新: 2026-08-26
関連ドキュメント: `requirements.md`（§5.3, §5.7, §5.8, §5.9, §5.10, §5.13）, `architecture.md`（§1.3, §4.3, §8.2, §9, §10）

## 1. 概要

サイト訪問者向けの公開ページ群（トップページ・記事詳細・タグ別一覧・検索・RSS・サイトマップ）と、それに付随するAPI（いいね、OGP画像生成）の仕様を定義する。すべて `architecture.md` §1.3 で決定した動的レンダリング（アクセスの都度D1参照＋Cache API）方式に基づく。

## 3. 画面仕様

### 3.1 トップページ（`/`、`/page/:n`）

- 公開済み記事（`status='published' AND published_at <= now()`）を新しい順に一覧表示
- 各記事：タイトル・公開日・読了時間・タグ（複数）・抜粋（description）・詳細ページへのリンク
- ページネーション（1ページあたり10件）

### 3.2 記事詳細ページ（`/posts/:slug`）

- タイトル・公開日・タグ・本文・いいねボタン（現在のいいね数を併記）
- 目次：見出し（`heading`ノード）から自動生成し、本文の前後2箇所に表示。各項目はアンカーリンク
- 脚注：本文中の参照箇所に上付きの番号、本文末尾に脚注一覧
- 未公開記事・存在しないslugへのアクセスは404（§7参照）

### 3.3 タグ別一覧ページ（`/tags/:slug`）

- タグ名を見出しとして表示し、該当記事を新しい順に一覧表示（トップページと同じカード形式）
- ページネーション対応

### 3.4 検索結果ページ（`/search?q=`）

- 検索ボックス＋結果一覧
- 各結果：タイトル・公開日・該当箇所のスニペット（検索語をハイライト表示）
- 該当0件の場合は「一致する記事が見つかりませんでした」を表示

### 3.5 404ページ

- Nuxtの標準エラーページ機構を利用し、「トップページに戻る」導線を表示する

## 4. API仕様

### 4.1 `GET /api/articles`

**Query**: `?page=1&limit=10`（既定値10件）

**Response 200**

```json
{
  "articles": [
    {
      "slug": "example-post",
      "title": "サンプル記事",
      "description": "記事の概要文",
      "publishedAt": "2026-08-01T09:00:00Z",
      "tags": [{ "name": "tech", "slug": "tech" }],
      "readingTimeMinutes": 6,
      "coverImageUrl": "/cdn-cgi/image/width=400/media/xxxx.jpg"
    }
  ],
  "pagination": { "page": 1, "totalPages": 5, "totalCount": 42 }
}
```

`status='published' AND published_at <= 現在時刻` の条件でフィルタする（予約中・下書きは含めない）。

### 4.2 `GET /api/articles/:slug`

**Response 200**

```json
{
  "slug": "example-post",
  "title": "サンプル記事",
  "description": "...",
  "bodyJson": { "type": "doc", "content": [] },
  "toc": [{ "level": 2, "text": "背景", "anchor": "背景" }],
  "footnotes": [{ "number": 1, "content": "脚注の内容" }],
  "publishedAt": "2026-08-01T09:00:00Z",
  "tags": [{ "name": "tech", "slug": "tech" }],
  "readingTimeMinutes": 6,
  "likeCount": 12
}
```

**Response 404**：`slug`が存在しない、または`status`が公開条件を満たさない場合

### 4.3 `GET /api/tags/:slug/articles`

**Response 200**

```json
{
  "tag": { "name": "tech", "slug": "tech" },
  "articles": ["...4.1と同じ形式..."],
  "pagination": { "page": 1, "totalPages": 1, "totalCount": 8 }
}
```

**Response 404**：該当タグが存在しない場合

### 4.4 `GET /api/search`

**Query**: `?q=検索語&page=1`

**Response 200**

```json
{
  "query": "cloudflare workers",
  "results": [
    {
      "slug": "example-post",
      "title": "サンプル記事",
      "snippet": "...Cloudflare <mark>Workers</mark>で構築した個人サイトの...",
      "publishedAt": "2026-08-01T09:00:00Z"
    }
  ],
  "pagination": { "page": 1, "totalPages": 1, "totalCount": 3 }
}
```

`snippet`はD1 FTS5の`snippet()`関数で生成し、該当語を`<mark>`タグで囲む。

### 4.5 `POST /api/articles/:id/like`

**Request**: ボディなし。`client_id`はCookie（未発行なら本APIの初回呼び出し時にサーバー側で発行しSet-Cookieする）から取得する

**Response 200**

```json
{ "likeCount": 13, "liked": true }
```

同一`client_id`からの2回目以降の呼び出しは、カウントを増やさず現在の状態をそのまま返す（冪等）。Cloudflare Rate Limitingにより、短時間の大量呼び出しは`429`で拒否される（`architecture.md` §8.2）。

### 4.6 `GET /api/rss.xml`

RSS 2.0形式。公開済み記事を新しい順に最大20件含む（タイトル・リンク・公開日・概要）。

### 4.7 `GET /sitemap.xml`

トップページ・全公開記事・全タグ別一覧ページのURLと`lastmod`を含むXMLサイトマップを動的生成する。

### 4.8 OGP画像生成

記事のOGP画像（PNG）を`nuxt-og-image`モジュール（takumi-rsベースの`.takumi.vue`テンプレート方式）で生成する（`architecture.md` §10）。当初想定していた独自の`GET /api/og/:slug`エンドポイントではなく、`nuxt-og-image`が自動発行するルートを利用する形に変更した（`app/pages/posts/[slug].vue`で`defineOgImageComponent('BlogPost', { title })`を呼び出すのみ）。

- キャッシュは`nuxt-og-image`側のデフォルト機構に従う。記事編集時のキャッシュ無効化が必要な場合は別途検討する
- 存在しない`slug`の場合は記事詳細ページ自体が404になるため、OGP画像も生成されない

## 5. データ仕様

`architecture.md` §3.2 の `articles` / `tags` / `article_tags` / `likes` テーブルを参照。本仕様書での追加要素は以下の通り。

| 項目                    | 仕様                                                                                                                         |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| いいねの`client_id`発行 | サーバー側でUUID等を生成し、`Set-Cookie`（`HttpOnly`, `SameSite=Lax`, 有効期限1年）で発行する                                |
| 検索対象                | `articles_fts`仮想テーブル（`title`, `body_text`）。`architecture.md` §9のとおり日本語分かち書き済みテキストを索引対象とする |

## 6. 処理フロー

### 6.1 目次（TOC）生成

記事詳細取得時（`GET /api/articles/:slug`）に、Worker側で`body_json`を走査し、`heading`ノード（`level`が2〜4）を抽出してTOCの配列を組み立てる。DBへの事前保存は行わず、リクエストの都度生成する。

### 6.2 読了時間の算出

`body_text`の文字数を、**400字/分**（既存サイトの実際の表示値から逆算した概算値に基づく）で割って概算する。小数点以下は切り上げ、最低1分として表示する。

### 6.3 いいね登録

1. クライアントがいいねボタンを押す
2. `POST /api/articles/:id/like` を呼び出す（Cookieに`client_id`が存在しなければサーバーが新規発行）
3. `likes`テーブルへ`INSERT`を試みる。`PRIMARY KEY (article_id, client_id)`により重複時は`INSERT`せず、現在のカウントをそのまま返す
4. クライアント側はレスポンスの`likeCount`で表示を更新し、ボタンを「いいね済み」の見た目に切り替える

### 6.4 検索

1. クライアントが検索語を入力し `GET /api/search?q=` を呼び出す
2. Worker側で検索語を`Intl.Segmenter`で分かち書きし、FTS5クエリへ変換する
3. `articles_fts`に対してBM25ランキングでクエリを実行し、`snippet()`でハイライト付き抜粋を生成する

## 7. エラーハンドリング

| ケース                                | 挙動                                                                             |
| ------------------------------------- | -------------------------------------------------------------------------------- |
| 存在しない/非公開の`slug`へのアクセス | 404ページを表示                                                                  |
| 検索語が空                            | クライアント側でAPI呼び出しを行わず、「検索語を入力してください」を表示          |
| いいねAPIのレート制限超過（429）      | ボタンを一時的に`disabled`にし、「しばらくしてからもう一度お試しください」を表示 |
| OGP画像生成の失敗                     | フォールバック用の汎用OGP画像（サイトロゴ等の静的画像）を返す                    |

## 8. 受け入れ基準

- [x] トップページに公開済み記事が新しい順に表示され、ページネーションが機能する（フェーズ2実装・検証済み）
- [x] 記事詳細ページで目次・脚注・いいねボタンが正しく表示・動作する（フェーズ2・4・5実装、Playwrightで実地検証済み）
- [x] タグ別一覧ページで該当記事が表示される（フェーズ5実装・検証済み）
- [x] 検索でキーワードにヒットする記事が表示され、該当箇所がハイライトされる（フェーズ5実装。日本語分かち書き検索の実地検証済み）
- [x] 同一クライアントから複数回いいねを押してもカウントが1回分しか増えない（フェーズ5実装・検証済み）
- [x] `/rss.xml`・`/sitemap.xml`が正しい形式で配信される（フェーズ5実装・検証済み）
- [x] 記事のOGP画像が生成され、SNS等でシェアした際にプレビューとして表示される（フェーズ5実装・検証済み。`nuxt-og-image` + `deployConfig: true`により日本語フォント込みで生成成功。`architecture.md` §10, §11.1参照）
- [x] 下書き・予約中の記事は一覧・検索・タグ一覧のいずれにも表示されない（フェーズ2・5で検証済み）

## 9. 決定事項・未決事項

**壁打ちを通じて決定した事項**

| 項目                    | 決定                                                                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| いいねのclient_id発行   | サーバー側でCookie発行（HttpOnly, 有効期限1年）                                                                                |
| いいねの重複防止        | `PRIMARY KEY (article_id, client_id)`で冪等に処理し、2回目以降はエラーにせず現在の状態を返す                                   |
| OGP画像生成方式         | `nuxt-og-image`モジュール（takumi-rsベースの`.takumi.vue`テンプレート）を採用。独自の`/api/og/:slug`エンドポイントは実装しない |
| 1ページあたりの表示件数 | 10件（トップページ・タグ別一覧共通）                                                                                           |
| 読了時間の算出係数      | 400字/分（既存サイトの表示値から逆算した概算値）                                                                               |

**未決事項**

なし。フェーズ5実装（トップページ・記事詳細・タグ一覧・検索・いいね・RSS/サイトマップ・OGP自動生成）は全て実装・検証済み。

タグ別一覧ページ・検索UIは、既存サイトのソース確認により「新規追加機能」と確定済み（`architecture.md` §4.3参照）。
