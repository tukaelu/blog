# 機能仕様書：既存記事の移行

最終更新: 2026-08-26
関連ドキュメント: `requirements.md`（§5.12）, `architecture.md`（§3.4）

---

## 1. 概要

既存サイト（[tukaelu/blog](https://github.com/tukaelu/blog)、Astro + Markdown/MDX）の記事を、新CMSの構造化データ（Tiptap JSON、D1）へ一括変換するCLI移行スクリプトの仕様。**一度きり実行するツール**であり、恒常的なAPI・UIは持たない。

## 2. 関連要件

| 要件定義書の項番     | 内容                                                        |
| -------------------- | ----------------------------------------------------------- |
| §5.12 既存記事の移行 | Markdown/MDXからTiptap JSONへの変換、フロントマターのD1移行 |

## 3. 前提：本仕様書の性質について

他の機能仕様書と異なり、本機能は**既存Markdownファイルの実際の記法（特にリンクカード・埋め込み等の独自表現）を精査しないと変換マッピングを完全に確定できない**。今回のドキュメント作成ではリポジトリ・ライブサイトの外形的な調査は行ったが、個々のMarkdownソースファイルの中身までは確認していない。そのため、本仕様書は「移行スクリプトの全体設計・処理フロー」を確定させるものとし、Markdown記法の詳細マッピングは実装着手時に既存記事のサンプルを精査した上で確定する前提とする（§9参照）。

---

## 4. スコープ

- **対象**：`contents/posts/ja` 配下のMarkdown/MDXファイル（10件）
- **対象外**：`contents/posts/en` 配下（2件）。新CMSの`articles`テーブルにロケール列がなく`slug`がテーブル全体でUNIQUE制約のため、ja/enで同一slugを持つ2記事（`zgsync-sync-markdown-to-zendesk-guide`, `sync-author-date-and-committer-date-in-git`）を両方移行すると衝突する。多言語対応は本プロジェクトのスコープ外（`requirements.md`にi18nの要件記載なし）のため、実装着手時にユーザー確認の上でenを対象外と決定した（2026-08-26、§9参照）
- **対象外**：移行スクリプト自体の永続化・スケジュール実行（一度きりの実行を想定）

---

## 5. 全体処理フロー

移行の本実行前に、**dry-runモード**（DBへの書き込みを行わず、変換結果と「要手動確認」リストのみを出力するモード）で一度スクリプトを走らせる。これにより、MDXコンポーネントの使用箇所・種類や、要手動確認になる記事の割合を、実装着手前の推測ではなく実際の走査結果として把握できる（§9参照）。

本実行時のフローは以下の通り。

1. `contents/posts` 配下のファイル一覧を取得する
2. 各ファイルについて以下を実行する：
   1. `gray-matter` でフロントマターと本文を分離する
   2. フロントマターから `title` / `tags` / 公開日等を抽出する
   3. Markdown本文を `remark` 等でASTにパースし、Tiptapのノード構造へマッピングする（§6）
   4. 本文中の画像参照（ローカルファイル・外部URL）を検出し、R2へアップロード。`media` テーブルへ登録し、本文中の参照を新しい配信URL（`spec-media.md`参照）へ置換する
   5. MDX特有の構文（Astroコンポーネントの埋め込み等）を検出した場合は自動変換せず、「要手動確認」リストへ記録する
   6. 変換結果を `articles` / `tags` / `article_tags` テーブルへ書き込み、初回の `article_revisions`（`revision_no: 1`）として記録する
3. 全ファイル処理後、変換件数のサマリと「要手動確認」リストをレポートとして出力する

## 6. Markdown → Tiptapノードのマッピング（暫定）

| Markdown要素                          | Tiptapノード                 | 備考                                                                                                                                                                                                                                                                                |
| ------------------------------------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 見出し（`#`〜）                       | `heading`                    | **仮の前提**：`#`（H1）は記事タイトルと重複するため本文中では使用されず、本文の見出しは`##`（H2）から始まると推定する（frontmatterの`title`と本文見出しを分離する一般的なパターン）。Tiptap側では`## → level 2`のまま対応させる                                                     |
| 段落                                  | `paragraph`                  |                                                                                                                                                                                                                                                                                     |
| 太字・斜体                            | `mark`（bold/italic）        |                                                                                                                                                                                                                                                                                     |
| リンク                                | `mark`（link）               |                                                                                                                                                                                                                                                                                     |
| 画像                                  | `image`                      | 移行後のR2 URLに差し替え                                                                                                                                                                                                                                                            |
| コードブロック（&#96;&#96;&#96;lang） | `codeBlock`                  | 言語指定をそのまま引き継ぐ                                                                                                                                                                                                                                                          |
| 引用（`>`）                           | `blockquote`                 |                                                                                                                                                                                                                                                                                     |
| リスト（`-`, `1.`）                   | `bulletList` / `orderedList` |                                                                                                                                                                                                                                                                                     |
| 脚注記法（`[^1]`）                    | `footnote`                   | ライブサイトで使用を確認済み                                                                                                                                                                                                                                                        |
| リンクカード的な表現                  | `linkCard`                   | **確定（実ソース確認済み）**：裸URL自動検出ではなく、`<EmbeddedLink url="..." />` というAstroコンポーネントの明示呼び出し方式だった（既存記事5件で使用）。移行スクリプトはMDX ASTから `EmbeddedLink` コンポーネント呼び出しのJSX要素を検出し、`url`属性を`linkCard`ノードへ変換する |
| GitHub/YouTube等の埋め込み            | `embed`                      | 既存記事での使用例は0件。変換ロジックは実装するが、実データでの検証はできない（新規執筆時にのみ使われる想定）                                                                                                                                                                       |

## 7. スラッグの扱い（確定：フォールバック方式）

既存記事のURL（`/posts/{slug}`）に含まれるスラッグを、可能な限りそのまま新CMSの`slug`として引き継ぐ。情報源は以下の優先順位で決定する。

1. フロントマターに`slug`フィールドがあればそれを使う
2. なければファイル名（拡張子を除く）を使う

いずれの場合も既存サイトの公開URLと一致するため、URL構造を変えずに済む（OGP画像パスのみ変更する方針は`architecture.md`決定事項の通り）。

## 8. エラーハンドリング・レポート

| ケース                                     | 挙動                                                                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| フロントマターの必須項目（タイトル等）欠落 | 変換をスキップし、エラーリストに記録する                                                                                 |
| MDX特有構文の検出                          | 変換は行わず「要手動確認」リストに記録し、処理は継続する                                                                 |
| 画像アップロード失敗                       | 該当記事を「要手動確認」リストに記録し、画像参照は元のパスのまま残す                                                     |
| スラッグの重複                             | 検出した時点で処理を中断し、手動での解消を促す（移行スクリプトは一括実行のため、重複は事前に解消しておくことが望ましい） |

## 9. 決定事項・未決事項

**壁打ちを通じて決定した事項**

| 項目                             | 決定                                                                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 移行スクリプトの性質             | 一度きり実行するCLIツールとする。恒常的な仕組みは持たない                                                                                   |
| 実行方式                         | 本実行前に必ずdry-runモード（DB書き込みなし）を実行し、変換結果と要手動確認リストを事前に確認する                                           |
| スラッグの情報源                 | フロントマターの`slug`フィールドを優先し、なければファイル名を使うフォールバック方式とする                                                  |
| リンクカード・埋め込みの想定記法 | **確定（実ソース確認済み、2026-08-26）**：`<EmbeddedLink url="..." />` というAstroコンポーネントの明示呼び出し方式。既存記事12件中5件で使用 |
| 見出しレベルの運用               | **確定（実ソース確認済み）**：既存記事12件は全て`##`（H2）/`###`（H3）のみを使用し、`#`（H1）の使用例はなかった                             |
| 移行対象の言語                   | **確定（2026-08-26）**：`contents/posts/ja`配下（10件）のみを対象とし、`en`配下（2件）は対象外とする。理由は§4参照                          |

**実ソース確認により解消した仮の前提（2026-08-26、`contents/posts`配下12記事を全件精査）**

1. リンクカード：裸URL自動検出ではなく`<EmbeddedLink url="..." />`コンポーネント呼び出し。移行スクリプトはMDX ASTから当該JSX要素を検出して`linkCard`ノードへ変換する
2. 埋め込み（GitHub/YouTube/X/Instagram）：**訂正（2026-08-26、実装時のdry-run結果で判明）**：「既存記事に使用例なし」という前提は誤りだった。`zgsync-sync-markdown-to-zendesk-guide`に埋め込みツイート（`<blockquote class="twitter-tweet">`形式のiframely/Twitter埋め込み）が1件存在する。ただしこの形式もEmbeddedLinkと同様の生JSXであり自動変換の対象外のため、他の未対応HTML/JSXと同じく「要手動確認」として検出され、移行実行そのものはブロックしない。移行後に管理画面のEmbed機能（provider: x）で手動再追加する想定
3. 見出しレベル：`##`から開始で確定
4. コードブロックのファイルパス指定：既存記事に使用例なし（言語指定のみ：`sh`/`js`/`javascript`/`error`）

**実装・dry-run実行により判明した項目（2026-08-26）**

- 対象10記事すべてがエラーなく変換できた。要手動確認になったのは、iframely/Twitter埋め込み等の生HTML/JSXブロック（6記事）、脚注定義にリンク書式が含まれ得るケース（1記事）、ローカル/外部画像のR2アップロード対象（5記事）
- フロントマターの`icon`（絵文字アイコンURL）と`unlisted`は新CMSのスキーマに存在しないため移行しない。`unlisted: true`だった記事（`design-renewal`, `starting-over`）は移行後は通常の公開記事として一覧に表示される（`requirements.md`の決定事項通り）
- 脚注ノード（`footnote`）はプレーンテキストのみを保持する設計のため、脚注定義にリンク等の書式が含まれる場合（`zgsync-sync-markdown-to-zendesk-guide`の`[^2]`）はテキストのみを残し、書式は失われる旨を要手動確認リストに記録する
